当 GPT-6 学会替你操作电脑：OS 级 Agent 的机会与风险

GPT-6 Astra 发布时，最让开发者兴奋的不是跑分，而是它被明确描述为”擅长代表用户操作电脑”。屏幕视觉理解加软件工程能力，意味着 Agent 正在从”聊天框里的顾问”变成”坐在你工位上替你干活的人”。这一步跨出去，机会和风险同样巨大。

为什么”操作电脑”是质变

过去两年的 Agent 大多是”会调用工具的程序”：读文件、发请求、跑命令，前提是每个动作都被预先定义成 API。而 OS 级 Agent 面对的是未经预处理的真实界面——截图、点按钮、填表单、跨应用协同。它的本质是把”会用电脑”这项人类技能模型化。

这项能力的想象空间很直接：报销、数据搬运、重复性录入、跨系统操作……大量”低技术含量但耗人”的白领工作第一次真正暴露在自动化射程内。而 GPT-6 把它放进旗舰叙事，等于向市场宣告：下一个主战场是”替人干活”，不是”陪人聊天”。

风险清单比机会清单更长

能力越大，需要回答的问题越多：

  1. 权限边界：一个能操作你电脑的模型，等于同时拥有了你所有应用的访问权。最小权限原则必须从”建议”变成”默认架构”；
  2. 误操作成本：人点错按钮有后果，Agent 点错按钮同样有后果，但责任归属却模糊得多——出事了算谁的？
  3. 提示注入放大：普通聊天场景里的一次恶意提示注入危害有限；当模型能执行系统级操作时，一份被污染的网页内容就可能让 Agent 帮你”把文件删了”或”把隐私发出去”；
  4. 审计与可回滚：自主执行必须以完整操作日志和可逆性为前提，否则任何企业都不敢放它进生产环境。

三类人会最先被改变

首当其冲的是重复性数字劳动密集的岗位；其次是”胶水型”开发——大量系统间数据搬运和集成工作可能被 Agent 直接替代；最后被改变的反而是管理者：他们要学的不是用 AI，而是给 AI 设定边界、验收结果、划分责任。

现在该做什么

对个人开发者：尽快把”我的工作流里哪些环节可以委托给 OS 级 Agent”列成清单，用小成本实验建立手感。对企业：先别急着全员开放，先在隔离环境里跑通”权限最小化 + 全量审计 + 人工审批关键操作”的三件套。

OS 级 Agent 会像所有生产力革命一样不可逆地到来。区别只在于：你是那个设计护栏的人，还是那个被它替代后才发现没有护栏的人。
