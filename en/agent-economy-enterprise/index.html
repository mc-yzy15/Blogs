Agent 经济落地企业：从 Demo 到发薪的最后一公里

千问办公首月 3000 万用户、各厂商 Agent 产品线不断拉长——Agent 经济的叙事已经足够丰满。但一个更冷静的观察是：真正在企业生产环境里”发薪干活”的 Agent 依然稀缺。 大多数 Agent 还停留在”能看不能用的 Demo”，从演示到上岗，隔着残酷的最后一公里。

Demo 与生产的差距在哪

Demo 里的 Agent 看起来无所不能，真实生产里的 Agent 却处处碰壁，差距来自四个现实：

  1. 数据是脏的：Demo 用干净样例，生产要面对缺失、重复、格式混乱的真实数据——Agent 的第一步”读数据”就可能崩溃；
  2. 异常没有剧本：Demo 只演示正常流程，生产里充满了权限变更、流程例外、历史遗留——Agent 遇到没见过的异常，往往直接卡死或瞎做；
  3. 责任没人敢接：Demo 里 Agent 做错了重来即可，生产里 Agent 做错一笔可能涉及真金白银——没有明确的责任机制，没人敢让 Agent 全自动；
  4. 成本不可控：Demo 跑一次的成本可以忽略，生产里每天几千次调用的账单会让 CFO 皱眉。

企业落地 Agent 的四步走

  1. 选对人机边界：先找”高频、规则清晰、错误代价低”的场景试点（如工单分类、报告初稿），让 Agent 证明自己，再逐步扩展；
  2. 人机协同而非无人值守：第一阶段的 Agent 定位是”提效助手”——自动做初稿，人工做终审。攒够信任数据后再谈自动化；
  3. 先通数据与权限：Agent 落地前，先把数据质量、权限体系、审批流这些”脏活”干完——它们是 Agent 的地基；
  4. 建立效果度量：用”节省工时、错误率、ROI”而非”Demo 演示效果”来评估 Agent——能度量，才能管理。

三个容易被忽略的坑

  1. Agent 也会”过拟合”：它可能只在你试点的场景表现好，换一批数据就打回原形——要持续用真实数据回测；
  2. 提示注入是企业级问题：当 Agent 读取外部邮件、网页内容时，恶意指令攻击会从”理论”变成”财务损失”；
  3. 运维是新成本中心：Agent 需要监控、告警、版本管理——别只算模型成本，把运维成本算进去。

结语

Agent 经济的下半场，比的不是谁家 Demo 更炫，而是谁先跑通”权限 + 数据 + 信任 + 度量”的最后一公里。3000 万用户的千问办公们证明了需求存在，接下来要证明的是：Agent 不仅能被试用，还能被长期、安全、盈利地使用。那才是 Agent 真正”发薪”的时刻。

**说明：**本文为 Agent 企业落地的实践观察，案例与数据引自公开报道。
