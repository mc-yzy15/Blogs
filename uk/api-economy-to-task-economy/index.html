从按 token 到按任务付费：AI 商业化的终局？

发表于2026-09-06|更新于2026-09-06|人工智能
|浏览量:

从按 token 到按任务付费：AI 商业化的终局？

过去两年，AI 行业的计费单位是 token——你问一句、它答一段，按字符消耗付费。这套模式在”人用模型”的时代成立，但当模型开始替人干活（写代码、审合同、管客服），问题就出现了：用户根本不在乎一次任务烧了多少 token，只在乎任务有没有完成、结果对不对。

token 计费的三重错位

  1. 激励错位：用户为”输入”付费，供应商没有动力让模型”少说废话高效完成”，反而 token 越多收入越高；
  2. 风险错位：一次失败的 Agent 任务可能消耗大量 token 却毫无产出，成本却全由用户承担；
  3. 心智错位：企业买的是”客服问题被解决”，不是”消耗了 3 万 token”——token 无法翻译成业务价值。

按任务付费的几种尝试

行业里已经出现向”成果”靠拢的定价实验：

  1. 按任务计费：明确”处理一张发票 X 元、生成一份合同 Y 元”，价格与 token 消耗解耦，供应商有动力优化效率；
  2. 按结果计费：更进一步，只在任务成功、可验收后收费（如代码通过测试、客服工单闭环）；
  3. 订阅 + 用量混合：基础订阅覆盖日常使用，重度任务按次加价——介于两种心智之间的过渡形态。

终局形态不会只有一种

按任务付费听着美好，落地却要解决两个难题：任务如何定义与计量（一次”写报告”包含多少工作？边界在哪）、结果如何验收（谁来判定成功？失败的锅是模型还是任务本身）。所以更可能出现的不是单一终局，而是分层：

  • 面向 C 端的对话与创作，继续沿用订阅制；
  • 面向 B 端的标准流程（客服、财务、审核），转向按任务/按结果付费；
  • 面向高价值定制场景，则是项目制与效果分成的混合。

从”卖算力”到”卖交付”

计价单位的变化，本质是 AI 行业角色的一次迁移：卖 token 的公司是”算力贩子”，卖任务的公司是”数字化劳动力供应商”。后者需要对交付质量负责，也要承担失败成本——这恰恰是 AI 从工具走向”同事”的必经之路。当供应商愿意为结果背书、按成功收费时，AI 商业化才算真正走出基建时代。

**说明：**本文为 AI 商业模式的趋势观察，实际定价以各厂商公布为准。
