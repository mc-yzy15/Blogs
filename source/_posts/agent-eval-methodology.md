# 怎么评估一个 Agent 真的能用

千问用"10 万元本金经营 365 天"来考 AI 店长，厂商们用"任务完成率"宣传自己的 Agent——但作为买家，怎么判断一个 Agent 在你的场景里真的能用？单看厂商的"完成率"远远不够，你需要一套自己的评估框架。

## 为什么"完成率"不够用

"任务完成率 90%"这个数字无法回答的问题太多了：任务集是什么？简单还是复杂？"完成"的定义是什么——是交付了结果，还是结果经过验证是对的？失败时是自动恢复还是需要人救火？**同一个 90%，可能是"只挑简单任务测"的结果，也可能是"真刀真枪"的成绩。**

## 四维评估框架

评估一个 Agent，建议从四个维度打分：

1. **端到端成功率**：从下任务到拿结果，不人工干预的成功比例。注意要分层统计——简单任务、中等任务、复杂任务分开报，别只看平均数；
2. **干预率**：每完成 N 个任务，需要人类介入多少次？这是"无人值守"程度的直接度量——比成功率更反映工程成熟度；
3. **错误严重度**：Agent 失败不可怕，可怕的是"失败得很危险"——把错误按"可自动恢复 / 需要修正 / 造成破坏"分级统计；
4. **成本效率**：完成一个任务消耗多少 token/时间/钱——再聪明，成本算不过来也没法生产使用。

## 评估的实操要点

1. **用你的任务，别用它的 Demo**：从真实业务里抽 30-50 个有代表性的任务做测试集——这是最贵也最值得的一步；
2. **测长尾与异常**：正常流程测不出 Agent 的成色，多放一些"缺数据、格式错、需求模糊"的刁钻用例；
3. **记录失败模式**：不要只记"失败了几次"，要记"为什么失败"——上下文丢失、工具调用错、还是规划断裂？失败模式决定改进方向；
4. **持续回归**：模型一更新、提示一调整，Agent 表现就会漂移——把评测集做成持续回归的流水线。

## 参考：动态经营评测的启发

千问 E-Commerce Bench 用"10 万本金经营 365 天看终局利润"的做法值得借鉴：它的核心不是考单点能力，而是考**长周期、多约束、结果导向的综合表现**。虽然模拟不等于现实，但"用终局结果打分"的思路，比"单点成功率"更能反映一个 Agent 在真实世界里的价值。

## 结语

评估 Agent 不能靠"感觉它能用"，也不能只看厂商宣传的完成率。**建立自己的四维评测框架，用真实任务持续回归**——这是你在 Agent 时代唯一可靠的选型方法。会评测的人，才能在 Agent 的营销迷雾里买到真正能干活的那个。

> **说明：**本文为 Agent 评测方法论，具体指标设计请结合业务场景调整。
