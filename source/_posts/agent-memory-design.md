# Agent 记忆设计入门：缓存、档案与遗忘

GPT-6 时代，模型上下文窗口已经可以塞下几十万 token——但 Agent 依然需要专门的记忆系统。因为"塞得下"不等于"记得住"，更不等于"能在正确的时候想起正确的事"。当 Agent 开始跑跨越多轮、持续数周的真实任务，记忆架构成为决定成败的隐藏变量。

## 三层记忆架构

参考人类记忆的分层，Agent 记忆通常设计为三层：

1. **工作记忆（短期）**：当前任务进行中的上下文——就是模型上下文窗口本身。设计要点是"够用即可"，塞太多无关内容反而会干扰推理；
2. **情景记忆（中期）**：跨会话的关键信息——之前处理过什么、用户偏好、进行到哪一步。通常存结构化记录或向量库，任务恢复时按需召回；
3. **语义记忆（长期）**：沉淀下来的领域知识、项目规范、历史决策——类似团队的 Wiki，为所有任务提供稳定的背景知识。

## 比"存"更重要的是"取"

大多数记忆系统做不好，不是因为存不下，而是因为取不对：

1. **相关性优先**：召回记忆时，只取与当前任务真正相关的片段——把十万条记忆全塞进上下文，等于没有记忆；
2. **时效性权重**：三个月前的决定可能已经过期，召回时要考虑时间衰减；
3. **来源可信度**：记忆里既有事实也有推测，要区分"确定的"与"可能过时的"——别让旧记忆误导新决策。

## 被忽略的"遗忘"设计

这是最反直觉也最重要的一点：**好的记忆系统必须会遗忘。**

1. **防上下文污染**：过时的偏好、已撤销的指令如果一直"活着"，会在某个任务里突然冒出来干扰 Agent；
2. **防记忆膨胀**：无边界累积的记忆会让每次召回的噪声越来越大、成本越来越高；
3. **隐私与合规**：记忆里存了大量用户数据，必须有保留期限与删除机制——"不忘"在合规上是灾难。

设计遗忘的策略：给每条记忆加生命周期、定期清理低价值记忆、对敏感记忆设置自动过期。

## 工程落地建议

1. **先手工后自动**：早期阶段用"结构化文件 + 人工维护"替代复杂向量库——先搞清楚你需要记什么，再上系统；
2. **记忆要可审计**：用户有权知道"Agent 记得我的什么"——记忆的透明度是信任的前提；
3. **分层使用不同技术**：短记忆用上下文管理，中记忆用向量检索，长记忆用知识库——一种技术打天下通常不够。

## 结语

Agent 记忆设计的本质，是回答三个问题：记住什么、怎么想起、何时忘记。**大多数团队把精力花在前两个，却忽略了"会遗忘"才是记忆系统成熟的标志。** 一个不会遗忘的 Agent，迟早会变成一个被自己的历史拖累的 Agent。

> **说明：**本文为 Agent 记忆架构的入门实践总结，具体设计请结合场景与数据规模。
