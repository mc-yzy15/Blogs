给 Agent 一台电脑之后：OS 权限治理手册

GPT-6 Astra 展示了”代表用户操作电脑”的能力，OS 级 Agent 从实验室走向办公桌只是时间问题。当一个能自主行动的 AI 拥有了你的屏幕、键盘与文件系统，最紧迫的问题不再是”它能不能干活”，而是”怎么给权限才不会出事”。以下是权限治理的实操手册。

权限设计的三层模型

给 Agent 权限，不要用”给/不给”的二元思维，要用三层模型：

  1. 可读层（默认开放）：读取文件、浏览网页、查询信息——这类操作风险低，可以默认允许，但要记录日志；
  2. 可写层（按需授权）：修改文件、发送消息、提交代码——这类操作会改变系统状态，必须按任务最小范围授权；
  3. 危险层（强管控）：执行命令、删除数据、访问密钥、涉及资金的转账——这类操作必须人工确认或双人复核。

落地的五个原则

  1. 最小权限：Agent 只能访问当前任务需要的文件与系统——绝不给”整个电脑”的钥匙；
  2. 会话级授权：权限跟着任务走，任务结束权限回收，不能”给一次用一年”；
  3. 敏感操作闸门：危险动作必须弹出确认——AI 不能自己给自己”放行”；
  4. 沙箱优先：能让 Agent 在虚拟机/容器里操作，就不放它进真实系统；
  5. 全量审计：记录 Agent 每一次读写执行，出问题时能完整回放它做了什么。

三个真实风险场景

  1. 提示注入越权：Agent 浏览网页时被植入恶意指令，诱导它执行危险操作——权限最小化是唯一有效的防线；
  2. 误操作级联：Agent 删了一个”看起来没用”的文件夹，结果那是生产环境的数据——需要可回滚的快照机制；
  3. 权限蔓延：开发者为了省事不断给 Agent 加权限，最终 Agent 拥有接近管理员的权限——定期权限审查必不可少。

企业部署 Checklist

  • 明确 Agent 能访问的应用与数据范围；
  • 危险操作清单（删除、转账、发信、部署）全部设人工闸门；
  • 所有 Agent 操作接入统一日志与审计；
  • 建立”Agent 出事故”的回滚与责任流程；
  • 定期（至少季度）重审 Agent 权限，收回不再需要的授权。

结语

OS 级 Agent 是生产力革命，也可能是安全黑洞——差别全在权限治理。给 AI 电脑权限，要像给实习生发门禁卡：只给他干活那层楼的门禁，敏感的机房永远需要你亲自刷卡。 先立好规矩再放开权限，是 2026 年所有想用 OS 级 Agent 的团队的第一课。

**说明：**本文为权限治理实践建议，具体方案请结合企业安全架构落地。
